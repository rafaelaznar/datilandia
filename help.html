Inicio y salpicadero

  • La página de inicio se abre al arrancar y al pulsar DATILANDIA en la barra superior. Sobre el título hay un salpicadero con las cifras del proyecto abierto; si no hay proyecto cargado, todas valen 0.
  • Tarjetas: tablas, filas, campos, claves ajenas, consultas, consultas con test, scripts, scripts con test, vistas (consultas y scripts que otro objeto usa como tabla), parejas relacionadas, dependencias (enlaces de consultas y scripts con las tablas, consultas o scripts que leen) y cobertura de pruebas (porcentaje de consultas y scripts con resultado asertado).
  • Tablas por filas: las seis tablas con más filas, con una barra comparativa y su número de filas; la pista del número recuerda el recuento completo.
  • Cobertura de pruebas: barra verde con el porcentaje y una nota con cuántas consultas y scripts llevan assert sobre el total.
  • Campos por tipo: cuántos campos son de texto, número y booleano, con una barra por tipo.
  • El salpicadero se repinta solo al abrir o crear un proyecto, al importar datos, al cambiar tablas, consultas, scripts o ajustes y al cambiar el idioma, así que siempre enseña las cifras del proyecto que tienes delante.

Importar datos

  • Ficheros: CSV y JSON, varios a la vez y mezclados. Cada fichero crea una tabla con su nombre (minúsculas, con _) y deja un informe con lo leído y los problemas encontrados.
  • CSV: comillas, comillas duplicadas, BOM y saltos CRLF. El separador se detecta solo, o lo eliges: , ; tabulador, espacio u otro.
  • JSON: un array de objetos con las mismas claves y valores simples.
  • Pegar texto: el formato se detecta solo (JSON si empieza por [ o {; si no, CSV).
  • Opciones: 1ª fila = cabecera, omitir filas inválidas. Después eliges el tipo de cada columna en una ventana aparte.
  • Tipos de las columnas: antes de crear la tabla (o de sustituir sus datos) se abre una ventana con una fila por columna, su tipo detectado, algunos ejemplos y el tipo a usar. En texto se guarda el valor tal cual —los ceros a la izquierda de un código no se pierden—; en número, solo lo que sea numérico; en booleano, null se queda nulo, false, 0 y la celda vacía son falso y cualquier otro valor es verdadero.

Tablas, filas y metadatos

  • Crear, renombrar y eliminar tablas, cada una con su descripción.
  • La lista de tablas se puede plegar desde su cabecera Todas las tablas: queda solo el título con el número de tablas, y el estado se guarda en el proyecto.
  • Añadir y borrar filas y editar cualquier celda; la fila en la que estás se marca en gris.
  • Campos y metadatos…: añadir, renombrar y borrar campos, con descripción y tipo (string, number, boolean); marca con una casilla cuál es el campo ID de la tabla (solo uno) y cuáles son claves ajenas, eligiendo la tabla y el campo de destino. Todo se guarda en el proyecto.
  • El campo ID es autonumérico: cada fila nueva recibe el siguiente número y ninguno se repite ni se reutiliza al borrar filas. Por eso no se edita a mano: se puede buscar en él, pero no se reemplaza. Con Crear campo ID autonumérico añades uno nuevo (el nombre se escribe a su lado), al principio de la tabla, y numera 1..N las filas que ya había. Marcar cualquier otro campo como ID también lo vuelve autonumérico.
  • La última columna de esa ventana, Es clave ajena, es la vista inversa y de solo lectura: qué campos de otras tablas apuntan a ese campo, uno por línea (o un guion si ninguno). Se edita desde la fila del campo que es la clave ajena. El destino de una clave ajena puede ser la propia tabla (aparece al final de la lista), para relaciones autorreferenciadas.
  • En la vista de la tabla, las claves ajenas se leen al pasar el ratón por su celda: la pista dice a qué tabla y campo apuntan y enseña el registro relacionado de la otra tabla (o avisa de que no existe), y el enlace ↗ abre la consulta con ese registro. Y si la tabla es el destino de alguna clave ajena, lleva una columna por cada una (← tabla.campo) con el número de filas de la otra tabla que traen cada fila: el propio número es un enlace que genera y ejecuta la consulta que las lista.
  • Buscar… y Reemplazar…: buscan y reemplazan en toda la tabla o en una columna, con los comodines * y ? (apartado «Buscar y reemplazar»).
  • Actualizar tabla… sustituye todos los datos de la tabla importando un CSV o JSON (fichero o pegado): funciona como Importar datos pero sin tocar la tabla, sus campos, sus claves ajenas ni las consultas que la usan. Antes de borrar los datos avisa, comprueba que coincidan los campos y la cabecera (si la primera fila es cabecera) y abre la ventana de tipos de las columnas, que propone el tipo de cada campo y el detectado; el campo ID autonumérico puede faltar. Si algo no coincide, no cambia nada y explica por qué.
  • El botón Fusionar tablas… de la cabecera crea una tabla nueva a partir de varias: escribe su nombre, marca al menos dos tablas y pulsa Fusionar. Los campos son la unión de todos, en el orden de la lista, y cada campo conserva la definición (nombre, tipo, descripción y claves ajenas) de la primera tabla que lo ofrece; las tablas pueden tener campos o tipos distintos. Las filas se concatenan en el orden de la lista y los campos que una tabla no tiene quedan null. Las tablas originales no se modifican y la nueva se añade al proyecto.
  • Exportar CSV… abre los datos de la tabla como texto CSV en una ventana, con Copiar y Descargar CSV y las mismas opciones de separador, cabecera y coma decimal que el resultado de una consulta.
  • Exportar JSON… descarga toda la tabla como array de objetos (uno por fila, con los nombres de los campos como claves), con sangría de dos espacios. No se limita a la página que ves: van todas las filas.
  • Renombrar sigue a las consultas: al cambiar el nombre de una tabla o de un campo, las consultas se reescriben solas (FROM tabla, tabla.campo, la columna suelta y los nombres asertados), también en el editor abierto. Se respetan los alias (AS nombre), los alias del FROM/JOIN, los textos, los comentarios y los corchetes de [nombre con espacios]. Solo se revisan las consultas que citan ese nombre, así renombrar sigue siendo rápido con muchas consultas.
  • Borrar avisa: antes de eliminar una tabla o un campo te dice cuántas consultas lo usan y cuáles, y después te recuerda las que se han quedado citando un nombre que ya no existe.
  • El tipo se infiere al importar, se puede cambiar a mano y se guarda en el proyecto. null no es un tipo: es información que falta. number admite decimales.
  • Páginas de filas con el total y salto a la primera o a la última.
  • Carpetas de tablas: las tablas se agrupan en carpetas igual, cada lista con las suyas: añadir carpeta añade una, arrastra una tabla hasta una carpeta para meterla dentro (o hasta «Sin carpeta» para sacarla), su cabecera la sube y la baja con sus flechas ▲ y ▼, la renombra, la borra y la pliega y el botón que hay a su lado pliega o despliega todas las carpetas de tablas de una vez. En el editor de la tabla el campo Carpeta es un desplegable con las carpetas de las tablas (y «Sin carpeta» para sacarla); el botón añadir carpeta del panel crea una nueva. Con carpetas de tablas el grupo «Todas las tablas» deja su sitio y el fichero las guarda en tableFolders, más cuáles están plegadas en foldedTableFolders. Las carpetas nunca cambian el SQL: dos tablas no pueden llamarse igual ni estando en carpetas distintas, y una consulta lee una tabla igual esté donde esté.
  • Pulsa el título Tablas o Consultas de la barra lateral para ver a la derecha la lista completa con sus propiedades: descripción, filas, campo ID y campos con su tipo; en las consultas, su assert y el resultado de las pruebas. Cada fila del resumen abre ese elemento.
  • En el resumen Tablas del proyecto, Ver estructura JSON… abre una ventana con la estructura de todas las tablas, la misma que muestra Estructura JSON… en cada tabla (sin las filas); dentro de esa ventana, Descargar estructura JSON guarda el JSON en un fichero.
  • El enlace Relaciones entre tablas y consultas abre la matriz de relaciones del proyecto: quién apunta a quién y qué consultas citan cada pareja de tablas. El detalle está en el apartado Relaciones.
  • El ancho de la columna izquierda es variable: arrastra el tirador entre la barra lateral y la vista (de 140 a 480 px), haz doble clic para volver a 480 px o usa las flechas con el tirador enfocado.

Consultas

  • Crear con +, ponerle nombre y descripción, y ejecutar con Ejecutar o Ctrl+Enter. Mientras una consulta o la batería de pruebas tarda, una ventana con un spinner dice qué se está ejecutando hasta que acaba.
  • Insertar tabla, consulta o campo… (encima del editor, o Ctrl+Space dentro de él) abre una lista con las tablas y las consultas del proyecto: pulsa un nombre para escribirlo en el cursor (con corchetes cuando el nombre los necesita) o pulsa la flecha para ver sus campos y pulsar uno. El buscador filtra la lista y los campos. A su lado, La leen como tabla (n) y Lee como tabla (n) despliegan las consultas que leen la abierta como tabla y las que ella lee, para saltar de una a otra; cada botón aparece solo cuando hay alguna.
  • Una consulta puede leerse desde otra como si fuera una tabla: escribe su nombre en el FROM y el motor la ejecuta al momento (apartado Ayuda SQL, «Consultas como tablas»). También al renombrarla se reescriben las consultas que la usan y, si la borras, te avisa de cuáles se quedan colgadas.
  • En la barra lateral, la consulta que alguna otra lee como tabla lleva la marca «vista» en azul, o «vista ×N» si la leen N consultas. Pasa el ratón por su pista y te dice los dos sentidos: «Lee como tabla (n): …» (a quién lee ella) y «La leen como tabla (n): …» (quién la lee a ella). La marca es solo información: no cambia lo que comprueba la consulta.
  • El resumen de consultas (el título Consultas de la barra lateral) lleva una columna Vistas con lo mismo, una línea por sentido (lee: «…» y la leen: «…»), o un guion si no hay ninguna. El salpicadero de la bienvenida cuenta en Consultas como tabla cuántas consultas del proyecto se leen así.
  • Ver relaciones abre una ventana con la matriz de relaciones entre las tablas del proyecto (las tablas en filas y columnas y, en cada cruce, la clave ajena que las une), como recordatorio mientras escribes la consulta (apartado Relaciones).
  • Antes del resultado verás el plan con el tiempo de cada paso; si algo falla, el error te dice línea, columna y qué revisar.
  • Resultados paginados (con total de filas y de páginas); clic en una fila para marcarla.
  • Exportar CSV… abre la ventana Resultado en CSV con la previsualización del resultado: Copiar lo lleva al portapapeles y Descargar CSV guarda el fichero con el nombre de la consulta (preguntando la carpeta, si el navegador tiene ventana de guardado).
  • El CSV se escribe con BOM para que Excel lo abra bien y con las opciones de esa misma ventana: separador (coma, punto y coma, tabulador, espacio u otro carácter), cabecera sí o no y coma decimal (3,14 en vez de 3.14; los textos no se tocan). Son las mismas opciones que las de Ajustes y se guardan dentro del proyecto.
  • La caja muestra todas las filas del resultado, para poder copiarlas todas de una vez, y el fichero descargado también va completo. Hay que ejecutar la consulta antes: sin resultado, la ventana te lo recuerda.
  • Son solo de lectura: nunca cambian los datos. En pantalla hay un tope de filas; el CSV exportado va completo.
  • Exportar JSON… descarga el resultado completo como array de objetos (uno por fila, con las columnas como claves), con sangría de dos espacios: van todas las filas, no solo la página que ves. Hay que ejecutar la consulta antes.
  • Cada consulta puede llevar su resultado asertado para el modo test: al abrir el proyecto se ejecuta y se compara con él (apartado «Modo test»). El botón Convertir en test del editor guarda el resultado que tienes en pantalla como ese resultado esperado.
  • Crear tabla… crea una tabla nueva con las columnas y filas del resultado que tienes en pantalla y te pide su nombre; el botón se habilita cuando la consulta tiene un resultado con filas. La consulta no cambia; si el resultado repite nombres de columna, se les añade un sufijo numérico.
  • Carpetas: crea una con el botón añadir carpeta de la cabecera del panel, arrastra una consulta hasta una carpeta para meterla dentro (o hasta «Sin carpeta» para sacarla) y renómbrala, duplícala con el botón de copiar de su cabecera (copia la carpeta con todas sus consultas) o bórrala desde ahí (las flechas de subir y bajar de su cabecera suben o bajan la carpeta en la lista); cada consulta de la lista lleva además sus acciones a la derecha: las flechas de subir y bajar la suben o la bajan dentro de su carpeta (se apagan en los extremos), el icono de copiar la duplica, la muestra de color pinta su fila con un color pastel (solo en la barra lateral; el fichero lo guarda en color) y el icono de la papelera la borra pidiendo confirmación; pliega o despliega sus consultas con la flecha de la cabecera (pulsar la cabecera hace lo mismo) o todas de una vez con el botón de plegar del panel. Borrar una carpeta no borra sus consultas: se quedan sin carpeta. En el editor, el campo Carpeta hace lo mismo eligiendo una de la lista desplegable (el botón añadir carpeta crea una nueva). El resumen de consultas lleva una columna con la carpeta de cada una y el fichero las guarda en folders, más cuáles están plegadas en foldedFolders. Al abrir un proyecto todas las carpetas empiezan plegadas (el grupo «Sin carpeta» se queda como está).

Relaciones entre tablas y consultas

  • El enlace Relaciones de la barra lateral abre una matriz con las tablas del proyecto en filas y columnas. En cada casilla de cruce se ve lo que une la tabla de la fila con la de la columna.
  • Dentro de la casilla van las claves ajenas de la tabla de la fila que apuntan a la de la columna, escritas como campo → campo destino. La diagonal recoge las autorreferencias: las claves ajenas de una tabla que apuntan a ella misma.
  • Al final de la casilla, en gris, el número de consultas que citan las dos tablas (con sus nombres en la pista del ratón). Se cuenta una vez por pareja, no en las dos casillas.
  • Bajo cada clave ajena van siete cifras con las filas del cruce, contadas sobre las dos tablas y nombradas con ellas: las de la tabla de la fila cuya clave es null, cuya clave no casa con ninguna fila de la de la columna o que encuentran su fila en ella, y las de la tabla de la columna sin ninguna, con alguna, con una exactamente o con más de una de la de la fila. El orden y qué significa cada una se explican en la leyenda de debajo de la matriz y en la pista de cada cifra.
  • Cada cifra mayor que 0 es un enlace: genera (o reutiliza) la consulta que devuelve exactamente esas filas, la deja seleccionada y la ejecuta, para que la compruebes.
  • Pulsa el nombre de una tabla en una cabecera de fila o de columna para abrir esa tabla.
  • Las cabeceras de fila quedan fijas al desplazar la matriz a lo ancho de la pantalla.
  • El botón Ver relaciones del editor de consultas abre la misma matriz en una ventana, como recordatorio mientras escribes: sin la columna de consultas ni los enlaces de las cifras. Se cierra con Esc o con Cerrar.

Dependencias

  • La entrada Dependencias de la barra lateral abre un árbol con las relaciones de todo el proyecto, sean tablas, consultas o scripts.
  • El selector Objeto elige la raíz. Dependencias muestra lo que ese objeto lee y Dependientes lo que lo lee; cada nodo se despliega con su flecha, se abre con su nombre o con el botón de abrir, y los ciclos se marcan como tales en vez de repetirse sin fin.
  • El grafo se calcula sin ejecutar nada: en las consultas se leen las fuentes del FROM/JOIN (también en subconsultas y uniones) y en los scripts los accesos literales tables["…"], queries["…"]() y scripts["…"](). Un acceso dinámico como tables[variable] se ejecuta, pero no aparece en el árbol ni se renombra solo.
  • Renombrar una tabla, una consulta o un script reescribe sus dependientes; al borrarlo se avisa de los que quedarán rotos. Los botones Orígenes de datos y Es origen de... de los editores muestran lo mismo agrupado, y la marca vista indica que otro objeto lo usa como fuente.

Scripts (JavaScript)

  • Los scripts se guardan en el proyecto (la clave scripts del JSON) y se ejecutan en el navegador. Cada uno tiene nombre, descripción y código; ya no tienen un «origen» fijo.
  • El panel Scripts de la barra lateral lista los scripts. El botón + crea uno; pulsa su nombre para abrir el editor.
  • Los datos se leen solo con tables (cada tabla por su nombre), queries (cada consulta por su nombre, como función: queries["ventas"]()) y scripts (cada script por su nombre, como función: scripts["resumen"]()).
  • El resultado de un script se puede usar como tabla en una consulta (escribe su nombre en el FROM) o desde otro script con scripts["nombre"]().
  • El resultado se muestra en un grid como el de las consultas. Devuelve un array de objetos (una columna por clave), un array de arrays (columnas c1, c2…) o un objeto (una fila); un valor suelto se muestra en la columna valor.
  • Puedes devolver el resultado con return o guardarlo en resultado. Si el script no devuelve nada, se avisa. Los objetos y arrays anidados se muestran como texto JSON.
  • Pulsa Ejecutar o Ctrl+Enter. Si hay un error, se indica el mensaje y la línea; el resultado se pagina con las filas por página de las consultas.
  • Si renombras una tabla, una consulta o un script, se actualizan las consultas y los scripts que lo usan. Al borrarlo se avisa de los dependientes que quedarán rotos.
  • Los botones Orígenes de datos y Es origen de... muestran, agrupados, las tablas, consultas y scripts que usa o que lo leen. La marca vista indica que otro objeto lo usa como fuente.
  • La entrada Dependencias, al final de la barra lateral, abre un árbol para explorar lo que lee un objeto y lo que lo lee, con selector de objeto y ambos sentidos.
  • Carpetas y color: el campo Carpeta del editor y la lista de scripts funcionan como en las consultas (crear, arrastrar, plegar, renombrar, duplicar y borrar). La muestra de color pinta la fila; los ficheros de prueba agrupan los scripts por tipo y usan un color para cada tipo.
  • Convertir en test guarda el resultado del script como assert; Quitar test lo elimina. Los scripts con test aparecen en Pruebas como un caso más del proyecto.
  • Crear tabla…, Exportar CSV… y Exportar JSON… trabajan sobre el resultado del script, igual que en las consultas.
  • Insertar tabla, consulta o campo… (o Ctrl+Space en el editor) escribe tables["…"], queries["…"](), scripts["…"]() o ["campo"] en el cursor.
  • Los cuatro ficheros de prueba traen una batería de scripts variados convertidos en tests, clasificados en carpetas y coloreados por tipo; las versiones en español e inglés llevan los mismos casos.
  • La carpeta Potencia de JavaScript de esos ficheros añade ocho casos avanzados: directorios con Intl.Collator, cruces de una consulta con una tabla (queries["…"]() + tables["…"]), fichas con Map y Set, clasificaciones con puestos compartidos, líneas temporales con Date, listas de control que ejecutan varias consultas de integridad, pivots por estado y equilibrios de carga con reduce.

Filtrar y transformar

Filtra las filas y quédate solo con las columnas que necesites. map crea un objeto nuevo por fila.

Agrupar con reduce

Acumula un objeto con las cuentas y conviértelo después en filas para el grid.

Guardar el resultado en resultado

Si no usas return, guarda el valor en resultado; también sirve para usar forEach y quedarte con un array aparte.

Filtrar y transformar

const rows = tables["sales"];
return rows
  .filter((row) => row.age > 30)
  .map((row) => ({ name: row.name, age: row.age }));

Agrupar con reduce

const rows = tables["sales"];
const byCity = rows.reduce((acc, row) => {
  acc[row.city] = (acc[row.city] || 0) + 1;
  return acc;
}, {});

return Object.entries(byCity)
  .map(([city, total]) => ({ city, total }));

Guardar el resultado en resultado

const rows = tables["sales"];
resultado = rows.map((row) => ({
  ...row,
  double: row.amount * 2,
}));

Leer una tabla, una consulta o otro script

tables, queries y scripts dan acceso a todo el proyecto. La consulta o el script se ejecutan al llamarlos.

const adults = queries["adults"]();
const sales = tables["sales"];

return adults.map((row) => ({
  name: row.name,
  total_sales: sales.filter((sale) => sale.customer_id === row.id).length,
}));

Combinar consultas, tablas y scripts

El resultado de una consulta se cruza con una tabla usando un Map, y el de un script se reutiliza llamándolo. Así el SQL aporta los cálculos y JavaScript el enriquecimiento, el formato, las fechas y las clasificaciones.

const summary = queries["sales_summary"]();
const customers = new Map(tables["customers"].map((c) => [c.id, c]));
const extra = scripts["vip_customers"]();

return summary.map((row, index) => {
  const customer = customers.get(row.customer_id);
  return {
    position: index + 1,
    customer: customer ? customer.name : "—",
    total: row.total,
    average: Math.round((row.total / row.orders) * 100) / 100,
    vip: extra.some((vip) => vip.customer_id === row.customer_id),
  };
});

Historial de lugares visitados

  • Bajo la barra superior hay una barra de histórico: un enlace redondeado a cada lugar por el que has pasado (inicio, una tabla, una consulta, un resumen, las relaciones o la importación). Al volver a una tabla o a una consulta, se revela en la barra lateral: se abre su carpeta si estaba plegada y la lista se desplaza hasta ella.
  • Pulsa un enlace para volver a ese lugar; el que está en pantalla queda resaltado. Volver a un lugar no lo repite (se mueve al final) y los enlaces a tablas o consultas que ya no existen desaparecen solos.
  • El histórico es de la sesión: no se guarda en el proyecto.

Proyecto y ajustes

  • Nuevo descarta el proyecto actual (te pregunta antes) y empieza uno vacío llamado «Sin título», abriendo Ajustes para que le pongas nombre.
  • Guardar proyecto (Ctrl+S) machaca su fichero; Guardar proyecto como pregunta dónde; al abrir otro, si hay cambios sin guardar te avisa antes de perderlos.
  • El nombre del proyecto se cambia en Ajustes; en la barra superior solo se muestra.
  • Mientras haya cambios pendientes verás «Cambios pendientes de guardar» arriba a la derecha, y también te avisa si intentas cerrar la pestaña.
  • Ajustes: filas por página de tablas y consultas y separador/cabecera por defecto al importar y al exportar. Todo eso se guarda dentro del propio proyecto.
  • El JSON se valida al abrirlo: si algo no cuadra te dice exactamente qué, incluido el resultado asertado (assert) de cada consulta. La antigua propiedad "testing" se acepta pero se ignora: el modo test se deduce de las consultas.

Modo test: consultas con resultado asertado

  • Un proyecto está en modo test cuando alguna de sus consultas comprueba un resultado (tiene assert): al abrirlo, datilandia ejecuta todas las consultas y compara cada resultado con el "assert" de esa consulta. Si ninguna consulta comprueba nada, el proyecto no es de test y no se ejecuta nada solo. No hay nada que declarar: la propiedad "testing" de los ficheros antiguos ya no hace falta.
  • Los scripts también pueden llevar su assert y se ejecutan en la misma batería: al abrir el proyecto, el informe incluye consultas y scripts, cada uno con su carpeta.
  • El "assert" es el resultado esperado de esa consulta: columns (nombres y orden de las columnas), rows (las filas esperadas, valor a valor), rowCount (solo cuántas filas) e ignoreOrder: true (mismo conjunto de filas, sin importar el orden). Basta con uno de los tres primeros para que la consulta se compruebe.
  • La comparación es estricta: null solo cuadra con null, un número no es un texto y 1 no es true. Renombrar una tabla o un campo ajusta también los nombres asertados, pero nunca los valores.
  • El informe se abre solo al cargar: resumen (consultas, correctas, fallidas y sin assert), una fila por consulta —sus filas, si lleva assert y el resultado— y el detalle de las diferencias, con lo esperado y lo obtenido en cada fila o columna que no cuadra. Si una consulta no compila, se marca como fallida con el error.
  • El botón Convertir en test del editor de consultas ejecuta esa consulta, guarda su resultado como su assert (columnas y filas, valor a valor) y pone el proyecto en modo test. Si la consulta ya comprobaba un resultado, te pregunta antes de sustituirlo; con Quitar test (activo solo si la consulta comprueba algo) vuelve a dejarla sin comprobar, sin sacar al proyecto del modo test.
  • El modo test del proyecto se ve arriba del todo a la derecha de la barra superior (modo test o sin test), y en la barra lateral cada consulta lleva su marca: test si tiene resultado asertado y sin test si no. El resumen de consultas lo detalla en su columna Assert.
  • Pulsa una fila del informe para abrir esa consulta en el editor; Re-ejecutar lanza otra vez la batería y Copiar informe lo deja como texto (si el navegador no deja copiar, queda seleccionado para Ctrl+C).
  • El botón Pruebas de la barra superior lanza la batería cuando quieras, pero solo aparece si el proyecto tiene algún test (alguna consulta o script con assert). Sin abrir ventanas: window.datilandia.runProjectTests().
  • El botón Auto-tests de la barra superior comprueba el propio programa (motor SQL, utilidades, ficheros e interfaz), no tus datos: ejecuta la batería interna y abre el Informe de auto-tests.
  • Ese informe lleva el recuento, una fila por caso —número, caso, resultado y detalle— y el bloque Casos que fallan con el motivo de cada uno. Re-ejecutar la lanza otra vez, Copiar informe lo deja como texto y Esc cierra la ventana.
  • La batería no toca tu proyecto: cada caso se ejecuta sobre datos de prueba y lo deja todo como estaba. Se ejecuta sin ningún proyecto cargado: con un proyecto abierto avisa y lo cierra (los cambios sin guardar se pierden). Sin ventana: window.datilandia.selfTest() devuelve el informe con el total, los aciertos, los fallos y el detalle de cada caso.
  • El formato completo del assert y un ejemplo, en los apartados de Ayuda SQL de esta página.

Buscar y reemplazar en la tabla

  • Buscar… y Reemplazar… (barra de la tabla): la misma ventana en dos modos; el modo reemplazo añade el campo con el texto nuevo y el botón Reemplazar todo.
  • El patrón es texto tal cual, con * para cualquier secuencia de caracteres y ? para uno solo: an*, *ana, ?an?????. La casilla distinguir mayúsculas decide si «ana» encuentra «Ana» (por defecto, sí lo encuentra).
  • El alcance lo elige el selector En:: todas las columnas o una sola. Las celdas null no se buscan y, sin patrón, no se busca nada.
  • El listado se actualiza mientras escribes, con una fila por celda —Fila · Campo · Valor · Coincidencias—, las coincidencias resaltadas dentro del valor y un resumen de coincidencias, celdas, filas y campos. Se listan hasta 500 coincidencias, pero el recuento es completo.
  • Pulsa una coincidencia y la ventana se cierra para dejarte en esa celda (cambia de página, la selecciona y el foco queda listo para corregirla a mano).
  • Al reemplazar, te pregunta antes con el recuento y el alcance, y sustituye todas las ocurrencias. El valor resultante se interpreta como al editar una celda (número, true/false, null o texto) y un reemplazo vacío borra lo encontrado.
  • El campo ID autonumérico nunca se modifica: se puede buscar en él, pero si eliges solo esa columna te avisa de que no se reemplaza.
  • Los comodines no tienen escape: un * o un ? literales no se pueden buscar.

Ayuda SQL · Forma general y dialecto

Forma general

SELECT [DISTINCT] columnas
FROM tabla [AS alias] [, otra AS alias]…
[INNER|LEFT [OUTER] JOIN tabla AS alias ON condición]
[WHERE condición]
[GROUP BY expresión [, …]] [HAVING condición]
[UNION [ALL] SELECT …]
[ORDER BY expresión [ASC|DESC] [NULLS FIRST|LAST] [, …]]
[LIMIT n [OFFSET m]]

Solo hay que escribir las partes que necesites, pero el orden es ese. Las palabras clave no distinguen mayúsculas de minúsculas. FROM es obligatorio: no hay SELECT sin tabla.

SELECT y DISTINCT

* trae todas las columnas; si no, una lista de columnas, expresiones o funciones separadas por comas. Cada elemento admite un alias, y el alias se escribe siempre con AS.

DISTINCT quita las filas repetidas comparando el conjunto de columnas seleccionadas.

Unir consultas: UNION y UNION ALL

UNION pega las filas de dos consultas una debajo de otra: las dos tienen que devolver el mismo número de columnas, en el mismo orden. UNION quita las filas repetidas; UNION ALL las deja todas. Se pueden encadenar más de dos consultas.

El ORDER BY y el LIMIT que van al final ordenan y cortan el resultado entero de la unión; ahí solo valen las columnas del resultado, por su nombre (AS) o por su posición (ORDER BY 2).

Todo de una tabla

SELECT * FROM alumnos;

Columnas, alias y expresiones

SELECT nombre AS alumno,
       edad,
       edad + 1 AS el_que_viene,
       UPPER(nombre) || ' (' || curso || ')' AS etiqueta
FROM alumnos;

Sin filas repetidas

SELECT DISTINCT curso
FROM alumnos
ORDER BY curso;

Dos cursos, uno debajo del otro

SELECT nombre, curso FROM alumnos_2025
UNION
SELECT nombre, curso FROM alumnos_2026
ORDER BY nombre;

Con repetidos: UNION ALL

SELECT curso FROM alumnos_2025
UNION ALL
SELECT curso FROM alumnos_2026
ORDER BY 1;

Lo que admite el dialecto

SELECT
Columnas, expresiones y *, con alias AS, y DISTINCT para no repetir filas.
FROM
Una tabla, o varias separadas por comas (join implícito) con alias: FROM ciclos AS c, familias AS f.
Consultas como tablas
En el FROM vale el nombre de cualquier consulta del proyecto: se ejecuta y su resultado se lee como una tabla (FROM ventas_2026 AS v), sola o unida a tablas y a otras consultas. Se pueden encadenar (vista de vista) y la consulta que alguien lee así lleva la marca «vista» en la barra lateral. Si el nombre coincide con el de una tabla, gana la tabla.
JOIN
INNER JOIN y LEFT [OUTER] JOIN con ON. Las igualdades entre tablas se resuelven con hash join, así que también va fino con tablas grandes.
WHERE
= == <> != < <= > >=, AND, OR, NOT; IS [NOT] NULL; [NOT] LIKE … [ESCAPE …]; [NOT] IN (…); [NOT] BETWEEN … AND …; [NOT] IN (SELECT …), [NOT] EXISTS (SELECT …), = ANY (SELECT …), >= ALL (SELECT …).
Subconsultas
Un SELECT entre paréntesis dentro de otro: con IN y NOT IN, con un comparador y ANY/SOME o ALL, y con [NOT] EXISTS (WHERE id IN (SELECT id FROM otra)). La subconsulta puede leer una consulta como tabla, y también va en el FROM con alias (tabla derivada): FROM (SELECT …) AS t. Si por dentro nombra columnas de fuera es correlacionada y se evalúa fila a fila. Como valor (en el SELECT o comparada) tiene que devolver una sola columna y una sola fila.
UNION
UNION y UNION ALL ponen debajo las filas de dos SELECT (y de más, encadenados): las dos partes devuelven el mismo número de columnas y UNION quita las filas repetidas, mientras que UNION ALL las conserva. El ORDER BY y el LIMIT finales valen para el resultado entero.
GROUP BY / HAVING
Agregados COUNT, SUM, AVG, MIN y MAX, con DISTINCT dentro: COUNT(DISTINCT puesto). HAVING filtra los grupos ya calculados.
ORDER BY
Varias columnas, ASC/DESC y NULLS FIRST/NULLS LAST. Un número es la posición de una columna del resultado: ORDER BY 2 DESC. Los textos numéricos se ordenan y comparan por valor, y el sitio de los valores que faltan lo manda NULLS FIRST/LAST aunque la clave sea DESC (sin indicarlo: primero en ASC, al final en DESC).
LIMIT / OFFSET
LIMIT 20 OFFSET 40 o al estilo MySQL LIMIT 40, 20 (primero el salto, después las filas).
Operadores
+ - * / %, concatenación || o CONCAT(…) y paréntesis. Una división por cero no falla: da null. Comentarios con -- o /* … */.
Literales e identificadores
'texto' y "texto" son ambos texto (para incluir la comilla, duplícala); [Nombre con espacios]; NULL, TRUE, FALSE.
Funciones
ABS, ROUND(x[, dec]) (la mitad se aleja del cero: 2,5 → 3 y −2,5 → −3), UPPER, LOWER, LENGTH, TRIM, SUBSTR(x, inicio[, largo]) (1 = primer carácter; los negativos cuentan desde el final), CONCAT(x, y, …) (textos unidos; null si algún argumento lo es), COALESCE, IFNULL, NULLIF.
Tipos y conversión
El tipo del campo convierte al consultar: un campo number con valores «31» responde a = 31, y uno boolean a = true. Los datos guardados no se tocan.
Solo lectura
Únicamente SELECT: no hay INSERT, UPDATE ni DELETE.

Los demás apartados de esta Ayuda SQL explican cada parte con ejemplos; los errores y los límites, en Límites y pruebas.

Ayuda SQL · Tablas, alias y vistas

FROM: tablas y alias

Se puede consultar una tabla o varias separadas por comas. El alias (con AS) acorta las referencias y evita ambigüedades: c.nombre. Si no hay dudas, también vale el nombre del campo a secas.

Varias tablas por comas equivalen a un join implícito: si además comparas campos de las dos en el WHERE, el motor lo convierte en un join de verdad.

Consultas como tablas

Cualquier consulta del proyecto se puede leer desde otra como si fuera una tabla: escribe su nombre en el FROM y el motor la ejecuta al ejecutar la consulta que la usa. Su resultado se trata como una tabla más (alias, JOIN, WHERE, GROUP BY…), con las columnas del SELECT de esa consulta —alias de salida incluidos— y una fila por fila del resultado.

Los nombres con espacios van entre corchetes: FROM [resumen de ventas] AS r. Si un nombre coincide con una tabla y con una consulta, gana la tabla. Las consultas se pueden encadenar (una que lee otra que lee otra), pero no en círculo: ninguna puede leer su propio resultado, ni directa ni indirectamente; si lo intentas, el error te enseña la cadena completa.

Si el resultado de esa consulta repite el nombre de una columna (por ejemplo SELECT a.x, b.x FROM …), al leerla como tabla solo se ve el último valor: dales alias distintos con AS.

La consulta se materializa antes de leerla: se ejecuta entera —su WHERE, sus JOIN, su GROUP BY/HAVING, su DISTINCT, su ORDER BY y su LIMIT/OFFSET— y lo que ve la consulta de fuera es su resultado ya hecho. Por eso el LIMIT de una vista llega ya recortado, y una vista que agrupa se puede volver a agregar (doble agregación).

Las consultas se pueden leer también dentro de una subconsulta y como tabla derivada: WHERE id IN (SELECT id FROM [resumen de ventas]) y FROM (SELECT …) AS t. Y una consulta cuyo SQL lleva una subconsulta sigue valiendo como vista: se ejecuta entera, subconsulta incluida (apartado Subconsultas).

Los tipos se conservan: un campo number sigue siendo número al leerlo desde fuera (se puede sumar, dividir o comparar con = 31), un boolean responde a = true y un null sigue siendo null (por eso valen COALESCE, IS NULL y ORDER BY … NULLS FIRST). Las columnas se llaman como los alias de salida de la vista.

En el FROM vale en cualquier posición: sola, con alias, unida a una tabla o a otra consulta (INNER JOIN y LEFT JOIN, incluida la anti-unión IS NULL), separada por comas, y también con la proyección alias.*. La misma vista dos veces en la misma consulta son dos fuentes independientes (y se calcula una sola vez por ejecución). Una vista que no devuelve filas es una tabla vacía, no un error: COUNT(*) da 0.

Encadenarlas es lo que da la vista de vista: una consulta que lee a otra que lee a otra, tantos niveles como quieras. La marca «vista» de la barra lateral y la columna Vistas del resumen de consultas te dicen quién lee a quién.

JOIN

INNER JOIN deja solo las filas que casan en las dos tablas; LEFT [OUTER] JOIN deja todas las de la izquierda y rellena con null donde no hay pareja (útil para buscar «los que no tienen»).

La condición va en ON. Cuando es una igualdad entre campos, el planificador la resuelve con hash join, así que también va rápido con tablas grandes. Sin condición obtienes el producto cartesiano: todas las combinaciones.

Join implícito por comas, con alias

SELECT c.nombre AS ciclo, f.descripcion AS familia
FROM ciclos AS c, familias AS f
WHERE c.codFamilia = f.codigo
ORDER BY c.nombre;

INNER JOIN

SELECT c.nombre AS ciclo, f.descripcion AS familia
FROM ciclos AS c
INNER JOIN familias AS f ON c.codFamilia = f.codigo
ORDER BY c.nombre;

LEFT JOIN: también los que no tienen pareja

SELECT f.descripcion AS familia, COUNT(c.nombre) AS ciclos
FROM familias AS f
LEFT JOIN ciclos AS c ON c.codFamilia = f.codigo
GROUP BY f.descripcion
ORDER BY ciclos ASC, familia;

Producto cartesiano: 5 alumnos × 3 ciclos = 15 filas

SELECT a.nombre, c.nombre AS ciclo
FROM alumnos AS a, ciclos AS c;

Consulta leída desde otra como si fuera una tabla

SELECT r.sede, r.edificios
FROM [Sedes con más edificios] AS r
WHERE r.edificios > 1
ORDER BY r.edificios DESC;

Vista de vista: una consulta que lee a otra que lee a otra

SELECT nivel, hospitales, camas
FROM [Niveles con dos o más hospitales]   -- esta, a su vez, lee otra consulta
WHERE camas >= 2000
ORDER BY camas DESC;

Subconsulta en el FROM: tabla derivada

SELECT t.sede, t.edificios
FROM (SELECT s.nombre AS sede, COUNT(e.id_edificio) AS edificios
      FROM sedes AS s
      INNER JOIN edificios AS e ON e.id_sede = s.id_sede
      GROUP BY s.nombre) AS t
WHERE t.edificios >= 2
ORDER BY t.edificios DESC;

La misma vista dos veces, con dos alias

SELECT a.codigo AS aula_1, b.codigo AS aula_2, a.capacidad
FROM [Aulas grandes] AS a
INNER JOIN [Aulas grandes] AS b
        ON b.capacidad = a.capacidad
       AND b.codigo > a.codigo
ORDER BY a.capacidad DESC, a.codigo, b.codigo;

Anti-unión con LEFT JOIN: los que no aparecen en una vista

SELECT e.nombre AS edificio
FROM edificios AS e
LEFT JOIN [Aulas y plazas por edificio] AS v ON v.id_edificio = e.id_edificio
WHERE v.aulas IS NULL
ORDER BY e.nombre;

Proyección con alias y asterisco sobre una vista

SELECT v.*
FROM [Aulas con proyector] AS v
ORDER BY v.capacidad DESC;

Ayuda SQL · Filtrar filas

WHERE: comparaciones

= y == para igualdad; <> y != para diferencia; <, <=, >, >= para orden.

Ojo con los valores que faltan: null = null no es cierto. Se pregunta con IS NULL y IS NOT NULL. Un campo number con textos «31» responde igual a = 31 (por el tipo del campo).

WHERE: texto

LIKE compara con comodines: % es «cualquier cosa» (también nada) y _ es «un carácter». Con ESCAPE '\' puedes buscar un % literal.

IN (lista) comprueba pertenencia a una lista de valores, y BETWEEN a AND b un rango incluyendo los extremos. Los tres se niegan con NOT delante.

Combinar condiciones

AND, OR y NOT, con paréntesis para dejar claro qué va con qué: (curso = 'A' OR curso = 'B') AND edad >= 18. Sin paréntesis, AND ata más fuerte que OR.

Subconsultas

Una subconsulta es un SELECT dentro de otro. Se usa con IN (y NOT IN), con un comparador y ANY/SOME o ALL, y con EXISTS (y NOT EXISTS). Puede leer una consulta usada como tabla y también ponerse en el FROM con un alias (tabla derivada). Si dentro nombra columnas de fuera es correlacionada y se evalúa fila a fila. Usada como valor, tiene que devolver una sola columna y una sola fila.

Comparar y filtrar

SELECT nombre, edad
FROM alumnos
WHERE curso = 'Grados D' AND edad >= 18;

Texto: comodines, listas y rangos

SELECT nombre, curso, edad
FROM alumnos
WHERE nombre LIKE 'A%'              -- empieza por A
   OR curso IN ('Grados A', 'Grados B')
   OR edad BETWEEN 18 AND 25;       -- extremos incluidos

Buscar el comodín como texto

SELECT nombre
FROM cursos
WHERE nombre LIKE '100\%' ESCAPE '\';           -- un % literal

Valores que faltan

SELECT nombre, COALESCE(edad, -1) AS edad
FROM alumnos
WHERE edad IS NULL OR telefono IS NOT NULL;

Resta de valores nulos y comparaciones seguras

SELECT NULLIF(TRIM(IFNULL(telefono, '')), '') AS telefono,
       nombre
FROM alumnos
WHERE NULLIF(TRIM(IFNULL(curso, '')), '') IS NOT NULL;

Subconsultas

SELECT nombre
FROM alumnos
WHERE curso IN (SELECT nombre FROM cursos WHERE activo = TRUE)
  AND EXISTS (SELECT 1 FROM matriculas
              WHERE matriculas.id_alumno = alumnos.id);

SELECT t.curso, t.total
FROM (SELECT curso, COUNT(*) AS total
      FROM alumnos
      GROUP BY curso) AS t
WHERE t.total > ALL (SELECT 1 FROM cursos);

Ayuda SQL · Resumir y ordenar

Agregados

COUNT(*) cuenta filas del grupo; COUNT(campo) cuenta solo los valores que no son null. SUM, AVG, MIN y MAX resumen la columna y también ignoran los null.

COUNT(DISTINCT campo) (y lo mismo con los demás agregados) cuenta valores distintos dentro del grupo.

GROUP BY y HAVING

GROUP BY junta las filas que comparten los valores indicados (una o varias columnas o expresiones). Las columnas del SELECT que no estén dentro de un agregado tienen que aparecer en el GROUP BY.

HAVING filtra grupos ya calculados (por eso puede usar agregados, al contrario que WHERE, que filtra filas antes).

ORDER BY

Varias claves separadas por comas, de la más importante a la menos. Cada una admite ASC (por defecto) o DESC, y NULLS FIRST / NULLS LAST para decidir dónde van los valores que faltan.

Se puede ordenar por una columna, por una expresión o por el alias de salida. Los textos que son números se ordenan por valor, así que «9» va antes que «10».

El sitio de los valores que faltan lo manda NULLS FIRST/NULLS LAST y no lo invierte DESC: sin decirlo, en ASC van primero y en DESC al final.

LIMIT y OFFSET

LIMIT n se queda con las n primeras filas del resultado ya ordenado, y OFFSET m se salta las m primeras: así se pagina. También se acepta el estilo MySQL LIMIT m, n (primero el salto).

Contar y agrupar

SELECT curso, COUNT(*) AS alumnos, AVG(edad) AS edad_media
FROM alumnos
GROUP BY curso
ORDER BY alumnos DESC;

Filtrar grupos con HAVING

SELECT depto,
       COUNT(*) AS n,
       ROUND(AVG(salario), 2) AS media
FROM empleados
GROUP BY depto
HAVING COUNT(*) >= 3 AND AVG(salario) > 1500
ORDER BY media DESC;

Valores distintos dentro de un agregado

SELECT COUNT(DISTINCT puesto) AS puestos,
       COUNT(*) AS empleados,
       MIN(fecha) AS primera,
       MAX(fecha) AS ultima
FROM empleados
WHERE activo = true;

Ordenar y paginar

SELECT nombre, edad
FROM alumnos
ORDER BY edad DESC NULLS LAST, nombre ASC
LIMIT 20 OFFSET 40;

Agregados sobre una vista (doble agregación)

SELECT COUNT(*) AS sedes,
       SUM(estudiantes) AS estudiantes,
       MIN(estudiantes) AS minimo,
       MAX(estudiantes) AS maximo
FROM [Estudiantes y correos por sede];   -- ya viene agrupada, una fila por sede

Paginación sobre una vista que ya trae su propio LIMIT

SELECT codigo, capacidad
FROM [Aulas grandes]           -- esta vista ya ordenó y recortó su resultado
ORDER BY capacidad DESC, codigo
LIMIT 3 OFFSET 2;

Ayuda SQL · Valores y funciones

Números, texto, nombres y null

Los números se escriben con punto decimal (3.5). 'texto' y "texto" son exactamente lo mismo: una cadena de texto. Para meter una comilla dentro, duplícala ('d''Artagnan').

Si el nombre de una columna o tabla lleva espacios o coincide con una palabra reservada, se escribe entre corchetes: [importe neto]. Además existen los valores NULL, TRUE y FALSE.

Operadores y comentarios

Aritmética con +, -, * y /; % da el resto de la división y || (o CONCAT(…)) concatena textos (números incluidos). Los paréntesis agrupan.

Dividir por cero no es un error: el resultado de esa operación es null.

Comentarios: -- hasta el final de la línea y /* … */ para varias líneas.

Funciones

ABS(x) valor absoluto · ROUND(x[, dec]) redondea a dec decimales (0 por defecto) · UPPER(x) y LOWER(x) cambian mayúsculas · LENGTH(x) número de caracteres · TRIM(x) quita espacios de los extremos · SUBSTR(x, inicio[, largo]) trozo de texto, con inicio 1 = primer carácter y negativos contando desde el final · CONCAT(a, b, …) une textos, con null si algún argumento lo es · COALESCE(a, b, …) primer valor que no sea null · IFNULL(a, b) b si a es null · NULLIF(a, b) null si a y b son iguales.

Se pueden anidar entre sí y usar tanto en el SELECT como en WHERE, GROUP BY u ORDER BY. Si el argumento es null, el resultado suele ser null.

Tipos de campo y conversión

Cada campo del proyecto tiene un tipo (string, number o boolean) que se usa al consultar: un campo number convierte sus textos a número, así que = 31, > 20 y SUM(campo) funcionan aunque el dato se importara como texto; uno boolean responde a = true.

La conversión no toca los datos guardados: solo afecta a la consulta. En un campo string, el texto '31' y el número 31 siguen siendo cosas distintas.

Funciones de texto en el SELECT y en el WHERE

SELECT TRIM(nombre) AS nombre,
       LENGTH(TRIM(nombre)) AS letras,
       CONCAT(SUBSTR(nombre, 1, 3), '…') AS iniciales,
       CONCAT(nombre, ' (', curso, ')') AS ficha,
       LOWER(curso) AS curso
FROM alumnos
WHERE LOWER(SUBSTR(nombre, 1, 1)) = 'a'
ORDER BY letras DESC;

Comentarios, comillas y nombres entre corchetes

-- Ventas sin anular (nombre con espacios)
SELECT [fecha pedido] AS fecha,
       importe,
       estado
FROM ventas                  /* ERP table */
WHERE estado <> 'anulada'
  AND descripcion LIKE '%"oferta"%'   -- comillas en texto
ORDER BY fecha DESC;

Ayuda SQL · Límites, cambios y pruebas

Errores, plan y límites

Si algo está mal escrito, el mensaje indica línea y columna, enseña el fragmento y sugiere el nombre más parecido. Al ejecutar, el plan muestra cada paso con su tiempo.

Las consultas son de solo lectura: no existen INSERT, UPDATE ni DELETE, ni tampoco CASE. Para cruzar tablas se usan joins y subconsultas; para juntar resultados, UNION.

Se ejecuta una sola sentencia: el ; final se acepta, pero no encadenes varias consultas separadas por ; (todo lo que vaya después se considera un error de sobra).

Cambios en los datos y en las consultas

Renombrar una tabla o un campo reescribe las consultas del proyecto que lo usan: el FROM/JOIN, las columnas cualificadas (tabla.campo) y la columna suelta. Se respetan los alias de salida (AS nombre), los alias del FROM/JOIN, los textos, los comentarios y los corchetes de [nombre con espacios]; un ORDER BY que apunta a un alias se queda como está.

El assert de cada consulta sigue al campo renombrado, salvo cuando el nombre lo produce un alias. El editor de la consulta abierta se actualiza al momento.

Borrar una tabla o un campo no reescribe nada: te avisa de cuántas consultas lo usan y cuáles, y después te recuerda las que se han quedado citando un nombre inexistente.

Consultas de prueba (modo test)

Un proyecto es de test cuando alguna de sus consultas comprueba un resultado: al abrirlo se ejecutan todas las consultas y se comparan con su "assert", y el informe se abre solo. La propiedad "testing" de los ficheros antiguos ya no hace falta (se ignora): el modo test se deduce de las consultas. Cada assert admite columns (nombres y orden de las columnas), rows (las filas esperadas, valor a valor), rowCount (solo cuántas filas) e ignoreOrder (comparar sin importar el orden).

La comparación es estricta: null solo cuadra con null, un número no es un texto y 1 no es true. Las consultas sin assert se ejecutan y se marcan como sin comprobar; las que no compilan, como fallidas con su error.

El botón Pruebas de la barra superior lanza la batería cuando quieras, pero solo se muestra si el proyecto tiene algún test. Para lanzarla sin abrir ventanas, con cualquier proyecto: window.datilandia.runProjectTests() devuelve el informe completo.

El botón Convertir en test del editor guarda el resultado actual de esa consulta como su assert (las columnas y todas las filas, valor a valor; rowCount: 0 si no devuelve ninguna) y pone el proyecto en modo test. En el fichero se escribe en forma compacta: columns, rows y, solo cuando aportan algo, rowCount e ignoreOrder. El modo test del proyecto y la marca de cada consulta se ven en la barra superior y en la barra lateral.

El botón Quitar test del editor hace lo contrario con esa consulta: le quita el assert (te pregunta antes) y deja de comprobarse, aunque el proyecto siga en modo test. La consulta se sigue ejecutando a mano con ▶ Ejecutar.

El botón Auto-tests lanza la batería interna del programa y abre su informe; sin ventana, window.datilandia.selfTest() devuelve el recuento y el detalle de cada caso.

Import data

  • Files: CSV and JSON, several at once and mixed. Each file creates a table with its name (lower case, with _) and leaves a report with what was read and the problems found.
  • CSV: quotes, doubled quotes, BOM and CRLF line breaks. The delimiter is detected on its own, or you choose it: , ; tab, space or another one.
  • JSON: an array of objects with the same keys and simple values.
  • Paste text: the format is detected on its own (JSON if it starts with [ or {; if not, CSV).
  • Options: 1st row = header, skip invalid rows. Afterwards you choose the type of each column in a separate window.

In text the value is stored as it comes —the leading zeros of a code are not lost—; in number, only what is numeric; in boolean, null stays null, false, 0 and the empty cell are false and any other value is true.

Tables, rows and metadata

  • Create, rename and delete tables, each one with its description.
  • The list of tables can be folded from its All tables header: only the title with the number of tables is left, and the state is saved in the project.
  • Add and delete rows and edit any cell; the row you are in is marked in grey.
  • Fields and metadata…: add, rename and delete fields, with description and type (string, number, boolean); tick a checkbox to say which one is the table's ID field (only one) and which ones are foreign keys, choosing the target table and field. Everything is saved in the project.
  • The ID field is auto-numbered: every new row gets the next number and none is repeated or reused when rows are deleted. That is why it is not edited by hand: it can be searched in, but it is not replaced. With Create auto-numbered ID field you add a new one (the name is written next to it), at the start of the table, and it numbers the rows that were already there 1..N. Marking any other field as ID also makes it auto-numbered.
  • The last column of that window, Is a foreign key, is the inverse and read-only view: which fields of other tables point to that field, one per line (or a dash if there are none). It is edited from the row of the field that is the foreign key. The target of a foreign key can be its own table (it appears at the end of the list), for self-referencing relations.

Before deleting the data it warns you, checks that the fields and the header match (if the first row is a header) and opens the column types window, which offers the type of each field and the detected one; the auto-numbered ID field may be left out. If something does not match, it changes nothing and says why.
  • The Merge tables… button in the header creates a new table from several: give it a name, tick at least two tables and press Merge. The fields are the union of all of them, in the order of the list, and each field keeps the definition (name, type, description and foreign keys) of the first table that has it; tables may have different fields or types. Rows are concatenated in the order of the list and fields a table does not have are left null. The original tables are not changed and the new one is added to the project.
  • Export CSV… opens the data of the table as CSV text in a window, with Copy and Download CSV and the same separator, header and decimal-comma options as the result of a query.
  • Export JSON… downloads the whole table as an array of objects (one per row, with the field names as keys), indented with two spaces. It is not limited to the page on screen: every row goes in.
  • Renaming follows the queries: when the name of a table or of a field changes, the queries rewrite themselves (FROM table, table.field, the bare column and the asserted names), also in the editor that is open. Aliases (AS name), the FROM/JOIN aliases, strings, comments and the brackets of [name with spaces] are respected. Only the queries that cite that name are reviewed, so renaming stays fast with many queries.
  • Deleting warns you: before removing a table or a field it tells you how many queries use it and which ones, and afterwards it reminds you of the ones left citing a name that no longer exists.
  • The type is inferred on import, it can be changed by hand and it is saved in the project. null is not a type: it is missing information. number accepts decimals.
  • Row pages with the total and a jump to the first or the last one.
  • Table folders: the tables are grouped in folders the same way, each one in its own list: add folder adds one, drag a table onto a folder to put it inside (or onto «No folder» to take it out), its header moves it up or down with its ▲ and ▼ arrows, renames it, deletes it and folds it and the button beside it folds or unfolds every folder of the tables at once. With folders of tables the «All tables» group steps aside and the file keeps them in tableFolders, plus which ones are folded in foldedTableFolders. Folders never change the SQL: two tables cannot share a name even if they are in different folders, and a query reads a table the same wherever it is.

Store the result in resultado

Filter and transform

const rows = tables["sales"];
return rows
  .filter((row) => row.age > 30)
  .map((row) => ({ name: row.name, age: row.age }));

Group with reduce

const rows = tables["sales"];
const byCity = rows.reduce((acc, row) => {
  acc[row.city] = (acc[row.city] || 0) + 1;
  return acc;
}, {});

return Object.entries(byCity)
  .map(([city, total]) => ({ city, total }));

Store the result in resultado

const rows = tables["sales"];
resultado = rows.map((row) => ({
  ...row,
  double: row.amount * 2,
}));

Read a table, a query or another script

tables, queries and scripts give access to the whole project. The query or script runs when it is called.

const adults = queries["adults"]();

return adults.map((row) => ({
  name: row.name,
  total_sales: sales.filter((sale) => sale.customer_id === row.id).length,

Combine queries, tables and scripts

A query result is crossed with a table using a Map, and a script result is reused by calling it. SQL brings the calculations and JavaScript brings the enrichment, formatting, dates and rankings.

const summary = queries["sales_summary"]();
const customers = new Map(tables["customers"].map((c) => [c.id, c]));
const extra = scripts["vip_customers"]();

return summary.map((row, index) => {
  const customer = customers.get(row.customer_id);
  return {
    position: index + 1,
    customer: customer ? customer.name : "—",
    total: row.total,
    average: Math.round((row.total / row.orders) * 100) / 100,
    vip: extra.some((vip) => vip.customer_id === row.customer_id),
  };
});

Test mode: queries with an asserted result

  • A project is in test mode when some of its queries checks a result (it has an assert): when it is opened, datilandia runs every query and compares each result with that query's "assert". If no query checks anything, the project is not a test one and nothing runs on its own. There is nothing to declare: the "testing" property of old files is no longer needed.
  • Scripts can also carry their assert and run in the same battery: when the project is opened, the report includes queries and scripts, each one with its folder.
  • The "assert" is the expected result of that query: columns (names and order of the columns), rows (the expected rows, value by value), rowCount (only how many rows) and ignoreOrder: true (same set of rows, whatever the order). One of the first three is enough for the query to be checked.
  • The comparison is strict: null only matches null, a number is not a text and 1 is not true. Renaming a table or a field also adjusts the asserted names, but never the values.
  • The report opens on its own when loading: a summary (queries, passed, failed and without an assert), one row per query —its rows, whether it carries an assert and the result— and the detail of the differences, with what was expected and what was obtained in every row or column that does not add up. If a query does not compile, it is marked as failed with the error.
  • The editor's Turn into a test button runs that query, saves its result as its assert (columns and rows, value by value) and puts the project in test mode. If the query already checked a result, it asks you before replacing it; with Remove test (only active if the query checks something) it goes back to checking nothing, without taking the project out of test mode.
  • The project's test mode is shown at the very top right of the top bar (test mode or no tests), and in the sidebar every query carries its mark: test if it has an asserted result and no tests if not. The query summary goes into detail in its Assert column.
  • Press a row of the report to open that query in the editor; Run again launches the battery once more and Copy report leaves it as text (if the browser does not allow copying, it stays selected for Ctrl+C).
  • The Tests button of the top bar launches the battery whenever you want, but it only appears if the project has some test (some query or script with an assert). Without opening windows: window.datilandia.runProjectTests().
  • The Self-tests button of the top bar checks the program itself (SQL engine, utilities, files and interface), not your data: it runs the internal battery and opens the Self-test report.
  • That report carries the count, one row per case —number, case, result and detail— and the Failing cases block with the reason of each one. Run again launches it once more, Copy report leaves it as text and Esc closes the window.
  • The battery does not touch your project: every case runs over test data and leaves everything as it was. It runs with no project loaded: with a project open it warns and closes it (unsaved changes are lost). Without a window: window.datilandia.selfTest() returns the report with the total, the passes, the failures and the detail of every case.
  • The complete format of the assert and an example are in the SQL help sections of this page.

SQL help · General shape and dialect

General shape

SELECT [DISTINCT] columnas
FROM tabla [AS alias] [, otra AS alias]…
[INNER|LEFT [OUTER] JOIN tabla AS alias ON condición]
[WHERE condición]
[GROUP BY expresión [, …]] [HAVING condición]
[UNION [ALL] SELECT …]
[ORDER BY expresión [ASC|DESC] [NULLS FIRST|LAST] [, …]]
[LIMIT n [OFFSET m]]

You only have to write the parts you need, but the order is that one. Keywords are not case-sensitive. FROM is compulsory: there is no SELECT without a table.

SELECT y DISTINCT

* brings all the columns; if not, a list of columns, expressions or functions separated by commas. Every item takes an alias, and the alias is written always with AS.

DISTINCT removes the repeated rows comparing the set of selected columns.

Combining queries: UNION and UNION ALL

UNION glues the rows of two queries one under the other: both must return the same number of columns, in the same order. UNION drops the repeated rows; UNION ALL keeps them all. More than two queries can be chained.

The ORDER BY and LIMIT written at the end sort and cut the whole result of the union; there only the columns of the result count, by their name (AS) or by their position (ORDER BY 2).

Everything from one table

SELECT * FROM alumnos;

Columns, aliases and expressions

SELECT nombre AS alumno,
       edad,
       edad + 1 AS el_que_viene,
       UPPER(nombre) || ' (' || curso || ')' AS etiqueta
FROM alumnos;

SELECT DISTINCT curso
FROM alumnos
ORDER BY curso;

SELECT nombre, curso FROM alumnos_2025
UNION

What the dialect supports

SELECT
Columns, expressions and *, with aliases AS, and DISTINCT to avoid repeating rows.
FROM
One table, or several separated by commas (implicit join) with aliases: FROM cycles AS c, families AS f.
Queries as tables
In the FROM the name of any query of the project is valid: it is run and its result is read as a table (FROM sales_2026 AS v), alone or joined to tables and to other queries. They can be chained (view of a view) and the query that somebody reads that way carries the «view» mark in the sidebar. If the name matches that of a table, the table wins.
JOIN
INNER JOIN and LEFT [OUTER] JOIN with ON. Equalities between tables are resolved with a hash join, so it is also smooth with big tables.
WHERE
= == <> != < <= > >=, AND, OR, NOT; IS [NOT] NULL; [NOT] LIKE … [ESCAPE …]; [NOT] IN (…); [NOT] BETWEEN … AND …; [NOT] IN (SELECT …), [NOT] EXISTS (SELECT …), = ANY (SELECT …), >= ALL (SELECT …).
Subqueries
A SELECT in brackets inside another one: with IN and NOT IN, with a comparison and ANY/SOME or ALL, and with [NOT] EXISTS (WHERE id IN (SELECT id FROM another)). The subquery can read a query as a table, and it can also go in the FROM with an alias (derived table): FROM (SELECT …) AS t. If it names outer columns inside it is correlated and runs row by row. Used as a value (in the SELECT or compared) it must return a single column and a single row.
UNION
UNION and UNION ALL stack the rows of two SELECTs (and of more, chained): both sides return the same number of columns and UNION drops the repeated rows, while UNION ALL keeps them. The final ORDER BY and LIMIT apply to the whole result.
GROUP BY / HAVING
Aggregates COUNT, SUM, AVG, MIN and MAX, with DISTINCT inside: COUNT(DISTINCT position). HAVING filters the groups already computed.
ORDER BY
Several columns, ASC/DESC and NULLS FIRST/NULLS LAST. A number is the position of a column of the result: ORDER BY 2 DESC. Numeric texts are sorted and compared by value, and where the missing values go is decided by NULLS FIRST/LAST even if the key is DESC (without saying it: first in ASC, at the end in DESC).
LIMIT / OFFSET
LIMIT 20 OFFSET 40 or MySQL style LIMIT 40, 20 (first the skip, then the rows).
Operators
+ - * / %, concatenation || or CONCAT(…) and parentheses. A division by zero does not fail: it gives null. Comments with -- or /* … */.
Literals and identifiers
'text' and "text" are both text (to include the quote, double it); [Name with spaces]; NULL, TRUE, FALSE.
Functions
ABS, ROUND(x[, dec]) (the half moves away from zero: 2.5 → 3 and −2.5 → −3), UPPER, LOWER, LENGTH, TRIM, SUBSTR(x, start[, length]) (1 = first character; negative ones count from the end), CONCAT(x, y, …) (texts joined; null if any argument is), COALESCE, IFNULL, NULLIF.
Types and conversion
The field type converts when querying: a number field with «31» values responds to = 31, and a boolean one to = true. The stored data is not touched.
Read-only
Only SELECT: there is no INSERT, UPDATE or DELETE.

SQL help · Tables, aliases and views

FROM: tables and aliases

One table can be queried, or several separated by commas. The alias (with AS) shortens the references and avoids ambiguities: c.name. If there is no doubt, the bare field name is also valid.

Several tables separated by commas are equivalent to an implicit join: if you also compare fields of both in the WHERE, the engine turns it into a real join.

Queries as tables

Any query of the project can be read from another as if it were a table: write its name in the FROM and the engine runs it when the query that uses it runs. Its result is treated as one more table (alias, JOIN, WHERE, GROUP BY…), with the columns of that query's SELECT —output aliases included— and one row per row of the result.

Names with spaces go in brackets: FROM [sales summary] AS r. If a name matches both a table and a query, the table wins. Queries can be chained (one that reads another that reads another), but not in a circle: none can read its own result, neither directly nor indirectly; if you try, the error shows you the whole chain.

If the result of that query repeats the name of a column (for instance SELECT a.x, b.x FROM …), when reading it as a table only the last value is seen: give them different aliases with AS.

The query is materialised before being read: it runs entirely —its WHERE, its JOIN, its GROUP BY/HAVING, its DISTINCT, its ORDER BY and its LIMIT/OFFSET— and what the outer query sees is its finished result. That is why the LIMIT of a view arrives already trimmed, and a view that groups can be aggregated again (double aggregation).

Queries can also be read inside a subquery and as a derived table: WHERE id IN (SELECT id FROM [sales summary]) and FROM (SELECT …) AS t. And a query whose SQL carries a subquery still works as a view: it runs whole, subquery included (section Subqueries).

The types are kept: a number field is still a number when read from outside (it can be added, divided or compared with = 31), a boolean responds to = true and a null is still null (that is why COALESCE, IS NULL and ORDER BY … NULLS FIRST work). The columns are named as the output aliases of the view.

In the FROM it is valid in any position: alone, with an alias, joined to a table or to another query (INNER JOIN and LEFT JOIN, including the anti-join IS NULL), separated by commas, and also with the projection alias.*. The same view twice in the same query are two independent sources (and it is computed only once per run). A view that returns no rows is an empty table, not an error: COUNT(*) gives 0.

Chaining them is what gives view of a view: a query that reads another that reads another, as many levels as you want. The «view» mark of the sidebar and the Views column of the query summary tell you who reads whom.

JOIN

INNER JOIN leaves only the rows that match in both tables; LEFT [OUTER] JOIN leaves all of the left one and fills with null where there is no pair (useful to find «those who do not have»).

The condition goes in ON. When it is an equality between fields, the planner resolves it with a hash join, so it is also fast with big tables. Without a condition you get the Cartesian product: every combination.

Implicit join with commas, with aliases

SELECT c.nombre AS ciclo, f.descripcion AS familia
FROM ciclos AS c, familias AS f
WHERE c.codFamilia = f.codigo
ORDER BY c.nombre;

INNER JOIN

SELECT c.nombre AS ciclo, f.descripcion AS familia
FROM ciclos AS c
INNER JOIN familias AS f ON c.codFamilia = f.codigo
ORDER BY c.nombre;

LEFT JOIN: also those with no pair

SELECT f.descripcion AS familia, COUNT(c.nombre) AS ciclos
FROM familias AS f
LEFT JOIN ciclos AS c ON c.codFamilia = f.codigo
GROUP BY f.descripcion
ORDER BY ciclos ASC, familia;

Cartesian product: 5 students × 3 cycles = 15 rows

SELECT a.nombre, c.nombre AS ciclo
FROM alumnos AS a, ciclos AS c;

A query read from another as if it were a table

SELECT r.sede, r.edificios
FROM [Sedes con más edificios] AS r
WHERE r.edificios > 1
ORDER BY r.edificios DESC;

View of a view: a query that reads another that reads another

SELECT nivel, hospitales, camas
FROM [Niveles con dos o más hospitales]   -- esta, a su vez, lee otra consulta
WHERE camas >= 2000
ORDER BY camas DESC;

Subquery in the FROM: derived table

SELECT t.sede, t.edificios
FROM (SELECT s.nombre AS sede, COUNT(e.id_edificio) AS edificios
      FROM sedes AS s
      INNER JOIN edificios AS e ON e.id_sede = s.id_sede
      GROUP BY s.nombre) AS t
WHERE t.edificios >= 2
ORDER BY t.edificios DESC;

The same view twice, with two aliases

SELECT a.codigo AS aula_1, b.codigo AS aula_2, a.capacidad
FROM [Aulas grandes] AS a
INNER JOIN [Aulas grandes] AS b
        ON b.capacidad = a.capacidad
       AND b.codigo > a.codigo
ORDER BY a.capacidad DESC, a.codigo, b.codigo;

Anti-join with LEFT JOIN: those that do not appear in a view

SELECT e.nombre AS edificio
FROM edificios AS e
LEFT JOIN [Aulas y plazas por edificio] AS v ON v.id_edificio = e.id_edificio
WHERE v.aulas IS NULL
ORDER BY e.nombre;

Projection with an alias and an asterisk over a view

SELECT v.*
FROM [Aulas con proyector] AS v
ORDER BY v.capacidad DESC;

SQL help · Filter rows

WHERE: comparisons

= and == for equality; <> and != for difference; <, <=, >, >= for order.

Beware of the missing values: null = null is not true. It is asked with IS NULL and IS NOT NULL. A number field with «31» texts responds the same to = 31 (because of the field type).

WHERE: text

LIKE compares with wildcards: % is «anything» (including nothing) and _ is «one character». With ESCAPE '\' you can search for a literal %.

IN (list) checks membership of a list of values, and BETWEEN a AND b a range including the ends. All three are negated with NOT in front.

Combining conditions

AND, OR and NOT, with parentheses to make clear what goes with what: (course = 'A' OR course = 'B') AND age >= 18. Without parentheses, AND binds tighter than OR.

Subqueries

A subquery is a SELECT inside another one. It is used with IN (and NOT IN), with a comparison and ANY/SOME or ALL, and with EXISTS (and NOT EXISTS). It can read a query used as a table and it can also go in the FROM with an alias (derived table). If it names outer columns inside it is correlated and runs row by row. Used as a value it must return a single column and a single row.

Compare and filter

SELECT nombre, edad
FROM alumnos
WHERE curso = 'Grados D' AND edad >= 18;

Text: wildcards, lists and ranges

SELECT nombre, curso, edad
FROM alumnos
WHERE nombre LIKE 'A%'              -- empieza por A
   OR curso IN ('Grados A', 'Grados B')
   OR edad BETWEEN 18 AND 25;       -- extremos incluidos

Search for the wildcard as text

SELECT nombre
FROM cursos
WHERE nombre LIKE '100\%' ESCAPE '\';           -- un % literal

Missing values

SELECT nombre, COALESCE(edad, -1) AS edad
FROM alumnos
WHERE edad IS NULL OR telefono IS NOT NULL;

Subtraction of null values and safe comparisons

SELECT NULLIF(TRIM(IFNULL(telefono, '')), '') AS telefono,
       nombre
FROM alumnos
WHERE NULLIF(TRIM(IFNULL(curso, '')), '') IS NOT NULL;

Subqueries

SELECT nombre
FROM alumnos
WHERE curso IN (SELECT nombre FROM cursos WHERE activo = TRUE)
  AND EXISTS (SELECT 1 FROM matriculas
              WHERE matriculas.id_alumno = alumnos.id);

SELECT t.curso, t.total
FROM (SELECT curso, COUNT(*) AS total
      FROM alumnos
      GROUP BY curso) AS t
WHERE t.total > ALL (SELECT 1 FROM cursos);

SQL help · Summarise and sort

Aggregates

COUNT(*) counts rows of the group; COUNT(field) counts only the values that are not null. SUM, AVG, MIN and MAX summarise the column and also ignore the nulls.

COUNT(DISTINCT field) (and the same with the other aggregates) counts distinct values inside the group.

GROUP BY y HAVING

GROUP BY joins the rows that share the given values (one or several columns or expressions). The columns of the SELECT that are not inside an aggregate have to appear in the GROUP BY.

HAVING filters groups already computed (that is why it can use aggregates, unlike WHERE, which filters rows beforehand).

ORDER BY

Several keys separated by commas, from the most important to the least. Each one takes ASC (by default) or DESC, and NULLS FIRST / NULLS LAST to decide where the missing values go.

It can be sorted by a column, by an expression or by the output alias. Texts that are numbers are sorted by value, so «9» goes before «10».

Where the missing values go is decided by NULLS FIRST/NULLS LAST and DESC does not flip it: without saying it, in ASC they go first and in DESC at the end.

LIMIT y OFFSET

LIMIT n keeps the first n rows of the result already sorted, and OFFSET m skips the first m: that is how you paginate. The MySQL style LIMIT m, n is also accepted (the skip first).

Count and group

SELECT curso, COUNT(*) AS alumnos, AVG(edad) AS edad_media
FROM alumnos
GROUP BY curso
ORDER BY alumnos DESC;

Filter groups with HAVING

SELECT depto,
       COUNT(*) AS n,
       ROUND(AVG(salario), 2) AS media
FROM empleados
GROUP BY depto
HAVING COUNT(*) >= 3 AND AVG(salario) > 1500
ORDER BY media DESC;

Distinct values inside an aggregate

SELECT COUNT(DISTINCT puesto) AS puestos,
       COUNT(*) AS empleados,
       MIN(fecha) AS primera,
       MAX(fecha) AS ultima
FROM empleados
WHERE activo = true;

Sort and paginate

SELECT nombre, edad
FROM alumnos
ORDER BY edad DESC NULLS LAST, nombre ASC
LIMIT 20 OFFSET 40;

Aggregates over a view (double aggregation)

SELECT COUNT(*) AS sedes,
       SUM(estudiantes) AS estudiantes,
       MIN(estudiantes) AS minimo,
       MAX(estudiantes) AS maximo
FROM [Estudiantes y correos por sede];   -- ya viene agrupada, una fila por sede

Pagination over a view that already brings its own LIMIT

SELECT codigo, capacidad
FROM [Aulas grandes]           -- esta vista ya ordenó y recortó su resultado
ORDER BY capacidad DESC, codigo
LIMIT 3 OFFSET 2;

SQL help · Values and functions

Numbers, text, names and null

Numbers are written with a decimal point (3.5). 'text' and "text" are exactly the same: a string of text. To put a quote inside, double it ('d''Artagnan').

If the name of a column or table has spaces or matches a reserved word, it is written in brackets: [net amount]. There are also the values NULL, TRUE and FALSE.

Operators and comments

Arithmetic with +, -, * and /; % gives the remainder of the division and || (or CONCAT(…)) concatenates texts (numbers included). Parentheses group.

Dividing by zero is not an error: the result of that operation is null.

Comments: -- to the end of the line and /* … */ for several lines.

Functions

ABS(x) absolute value · ROUND(x[, dec]) rounds to dec decimals (0 by default) · UPPER(x) and LOWER(x) change the case · LENGTH(x) number of characters · TRIM(x) removes spaces from the ends · SUBSTR(x, start[, length]) piece of text, with start 1 = first character and negative ones counting from the end · CONCAT(a, b, …) joins texts, with null if any argument is · COALESCE(a, b, …) first value that is not null · IFNULL(a, b) b if a is null · NULLIF(a, b) null if a and b are equal.

They can be nested inside each other and used both in the SELECT and in the WHERE, GROUP BY or ORDER BY. If the argument is null, the result is usually null.

Field types and conversion

Every field of the project has a type (string, number or boolean) that is used when querying: a number field converts its texts to a number, so = 31, > 20 and SUM(field) work even if the data was imported as text; a boolean one responds to = true.

The conversion does not touch the stored data: it only affects the query. In a string field, the text '31' and the number 31 are still different things.

Text functions in the SELECT and in the WHERE

SELECT TRIM(nombre) AS nombre,
       LENGTH(TRIM(nombre)) AS letras,
       CONCAT(SUBSTR(nombre, 1, 3), '…') AS iniciales,
       CONCAT(nombre, ' (', curso, ')') AS ficha,
       LOWER(curso) AS curso
FROM alumnos
WHERE LOWER(SUBSTR(nombre, 1, 1)) = 'a'
ORDER BY letras DESC;

Comments, quotes and names in brackets

-- Ventas sin anular (nombre con espacios)
SELECT [fecha pedido] AS fecha,
       importe,
       estado
FROM ventas                  /* ERP table */
WHERE estado <> 'anulada'
  AND descripcion LIKE '%"oferta"%'   -- comillas en texto
ORDER BY fecha DESC;

SQL help · Limits, changes and tests

Errors, plan and limits

If something is badly written, the message gives line and column, shows the fragment and suggests the closest name. When running, the plan shows every step with its time.

Queries are read-only: there is no INSERT, UPDATE or DELETE, and neither CASE. Joins and subqueries are used to cross tables; UNION to stack results.

One single statement runs: the final ; is accepted, but do not chain several queries separated by ; (everything after it is treated as a spurious error).

Changes in the data and in the queries

Renaming a table or a field rewrites the queries of the project that use it: the FROM/JOIN, the qualified columns (table.field) and the bare column. Output aliases (AS name), the FROM/JOIN aliases, strings, comments and the brackets of [name with spaces] are respected; an ORDER BY pointing at an alias stays as it is.

Every query's assert follows the renamed field, except when the name comes from an alias. The editor of the open query updates straight away.

Deleting a table or a field rewrites nothing: it tells you how many queries use it and which ones, and afterwards it reminds you of the ones left citing a name that does not exist.

Test queries (test mode)

A project is a test one when some of its queries checks a result: when it is opened all the queries run and are compared with their "assert", and the report opens on its own. The "testing" property of old files is no longer needed (it is ignored): test mode is worked out from the queries. Every assert takes columns (names and order of the columns), rows (the expected rows, value by value), rowCount (only how many rows) and ignoreOrder (compare whatever the order).

The comparison is strict: null only matches null, a number is not a text and 1 is not true. Queries without an assert run and are marked as unchecked; those that do not compile, as failed with their error.

The Tests button of the top bar launches the battery whenever you want, but it is only shown if the project has some test. To launch it without opening windows, with any project: window.datilandia.runProjectTests() returns the complete report.

The editor's Turn into a test button saves the current result of that query as its assert (the columns and every row, value by value; rowCount: 0 if it returns none) and puts the project in test mode. In the file it is written in a compact form: columns, rows and, only when they add something, rowCount and ignoreOrder. The test mode of the project and the mark of every query are shown in the top bar and in the sidebar.

The editor's Remove test button does the opposite with that query: it removes its assert (it asks you first) and it stops being checked, although the project stays in test mode. The query is still run by hand with ▶ Run.

The Self-tests button launches the program's internal battery and opens its report; without a window, window.datilandia.selfTest() returns the count and the detail of every case.
